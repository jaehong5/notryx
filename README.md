# Notryx

파일 기반 셀프호스팅 Markdown 작업 공간을 개발하고 있다. 현재 버전은 `0.1.0`이다. M3 Linux 개인 시험판을 준비 중이며, 두 독립 Linux 앱의 문서 편집과 동기화, 서버 재연결, 충돌 해결 및 휴지통 복원을 검증했다. M3 전체 게이트 통과나 운영판 출시를 뜻하지 않는다.

Linux 클라이언트는 기기 초안과 조건부 서버 저장, 기본 Markdown 미리보기, 기기 캐시 검색을 제공한다. 오프라인에서는 기기에 저장된 문서와 초안을 열 수 있다. 충돌 시 원문을 대조하고 서버 본문 선택, 합본 또는 사본 저장을 명시적으로 진행한다.

Linux 서버는 기기 등록, 파일과 폴더 생성, 목록과 원문 조회, 조건부 저장, 이동, 삭제 및 휴지통 복원을 제공한다. 변경 이력과 SSE 알림, 최대 25 MiB 첨부 업로드, 작업 결과 재조회와 재시도, receipt ACK와 미접수 작업 취소를 지원한다. 재시작 복구, 로컬 관리자의 격리 해결, 수동 온라인 백업과 서버 중단 상태의 백업, 빈 경로 복원, Docker 개발 실행 구성도 제공한다.

- 개발 서버 실행과 기기 등록: [서버 안내](docs/development.md#개발-서버-실행과-조회)
- 서버 Docker 빌드와 격리 실행: [Docker 안내](docs/deployment.md)

서버의 Markdown 저장 위치는 설정 파일의 `notes_root` 또는 Docker Compose의 `NOTRYX_NOTES_DIR`로 지정한다. 기존 저장소를 다른 위치로 옮기는 작업은 경로 설정 변경과 별도로 처리해야 한다.

## 실행

개발 도구를 설치한 Bash에서 실행한다.

```bash
source "${NVM_DIR:-$HOME/.nvm}/nvm.sh"
nvm use
source scripts/dev-env.sh
npm ci
npm run tauri -- dev
```

서버를 실행한 뒤 [기기 등록 절차](docs/development.md#로컬-관리자와-기기-등록)에 따라 일회용 등록 비밀을 발급한다. 앱의 연결 화면에 서버 주소, 작업 공간 ID와 등록 비밀을 입력한다. 다른 PC에서 접속할 때는 그 PC가 접근할 수 있는 HTTPS 주소를 사용한다. `127.0.0.1` HTTP 예제는 같은 PC의 개발 시험용이다.

새 문서는 LF를 사용한다. 기존 문서를 수정하지 않으면 bytes를 유지하며, 유효 UTF-8 문서를 실제 편집하면 전체 줄바꿈을 LF로 저장한다. CRLF, 혼합 줄바꿈과 단독 CR 문서는 편집 전에 저장 정책을 안내한다. BOM과 알 수 없는 문법을 유지한다. BOM을 포함한 원문 bytes가 5 MiB 이하인 유효 UTF-8 문서를 편집할 수 있다. 5 MiB 초과부터 25 MiB 이하인 문서와 25 MiB 이하인 비UTF-8 문서는 읽기 전용으로 열며, 25 MiB 초과 문서는 열 수 없다.

시험 앱은 OS 앱 데이터 디렉터리의 `org.notryx.m0`에 `drafts.sqlite3`를 만든다. 별도 시험 저장소를 지정하려면 native 프로세스 환경변수 `NOTRYX_M0_DATA_DIR`를 사용한다. 초안은 평문 SQLite에 저장된다. Linux Secret Service에 인증정보를 저장한 경우 재시작 시 기기 신원을 확인하고 연결을 복원한다. 비밀 저장소를 사용할 수 없어 세션 전용으로 등록했다면 재시작 후 다시 등록해야 한다. 이전 등록의 초안과 전송 대기 자료는 기기에 보존하며 자동 재전송하지 않는다. 대조와 사용자 선택에 따른 복구 화면을 제공한다.

Linux에서 열린 문서의 원문을 복사하거나 새 파일로 내보낼 수 있다. 파일 내보내기는 기존 파일을 덮어쓰지 않는다. 로컬 DB 마이그레이션이 실패하면 편집과 전송을 중지하고 복구 화면에서 읽을 수 있는 초안, base, 전송 대기 원문 또는 WAL의 변경이 반영된 DB 사본을 내보낼 수 있다.

## 검사

```bash
bash scripts/check.sh
cargo test --locked -p notryx-server -p notryx-server-storage
npm run tauri -- build --debug --no-bundle
npm run tauri -- android build --debug --target aarch64 --apk --ci
```

Linux CI는 전체 검사와 실제 Tauri 앱의 두 클라이언트 사용 흐름을 실행한다. Docker CI는 서버 이미지 빌드와 격리 실행을 검사하며 이미지를 게시하거나 서버에 배포하지 않는다.

남은 검증과 제한은 다음과 같다.

- 기존 편집기 성능 기준과 캐시 검색의 진행 표시 지연 기준은 미통과다.
- cold backup과 두 앱의 복원 후 자료 보존은 같은 디스크에서 검증했다. 별도 디스크나 원격 저장소의 독립 백업 보관은 아직 검증하지 않았다.
- 실제 사용자 키링을 사용하는 앱 재시작, 현재 버전의 물리 Linux 한글 IME 및 전원 장애는 미검증이다. 자동 시험은 이를 대신하지 않는다.
- Android 실기기와 두 한글 키보드 시험을 통과하기 전에는 Android 지원이나 M0 전체 통과를 선언하지 않는다.

수동 온라인 백업과 복원, 기기 token 연장 API와 클라이언트 자동 연장 및 만료 안내를 구현했다. gateway 인증 등 나머지 Linux 운영판 기능과 전체 운영 검증은 후속 범위다.

프로젝트 라이선스와 공개 배포 안내는 아직 확정하지 않았다. 현재 코드를 라이선스가 부여된 공개 릴리스로 취급하지 않는다.
